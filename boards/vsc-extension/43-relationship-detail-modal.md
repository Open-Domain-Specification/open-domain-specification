# Relationship detail opens in a modal, not a bottom sheet

The bottom sheet (card 41) removed the nested table, but it is the wrong container. Seen in the extension at editor height it takes roughly 40% of a webview that is already short, pushes the Strategic position table up, clips the context map below it, and scrolls the row you expanded out of sight, so the detail loses the row it belongs to. Replace it with a modal.

Read what the card turns on: `packages/pages/src/lib/atoms/BottomSheet.svelte:1-190`, the sheet it replaces; `packages/pages/src/lib/organisms/StrategicPositionTable.svelte:113-142`, its only caller; `packages/pages/src/lib/organisms/RelationshipDetail.svelte:74-155`, the content it has to hold — a title, a description, a definition list of roles, a comment list, a four-column crossings table and a links list. The design calls, each with its reason, before any code:
  1. **Not the native `<dialog>` element.** I wanted it — top layer, a real focus trap, `::backdrop` and Escape for nothing — but the unit suite runs on jsdom 30.0.1, whose `HTMLDialogElement.prototype` carries `open` and nothing else: `showModal` is not a function, so the component would throw in every test that renders a Strategic position table, and this package's gate is 100% coverage from those tests. Polyfilling it in `src/lib/test-setup.ts` would mean the tests exercise the polyfill, not the trap. So the modal is a `role="dialog"` panel with `aria-modal`, its own scrim and its own Tab ring, all of it real code with real tests, and the real browser checks the same behaviours again in Playwright.
  2. **Over everything, at `z-index: 1100`.** The one surface that takes the page away from the reader must be above everything the page can draw, and the tallest thing it can draw is the fullscreen diagram overlay at 1000 (`organisms/InteractiveDiagram.svelte:88`).
  3. **A scrim, and the design language line changes.** The sheet was told to have none because VS Code's bottom panel has none; a dialog is the opposite case — the platform dims the whole workbench behind it, and the dim is what says the page cannot be reached. There is no theme token for that block, and it is the same wash in every VS Code theme, so it is a constant here too: `rgb(0 0 0 / 0.44)` at `atoms/Modal.svelte:151-158`.
  4. **Focus lands on the panel, not the close button.** A reader arrives at the title rather than at "close", and the first Tab from there is the close button anyway (`atoms/Modal.svelte:66-77`).
  5. **A hairline under the title row** (`atoms/Modal.svelte:184-193`), which the platform's dialog does not have: the platform's dialog holds a sentence, this one holds a table that scrolls under the header, and a scrolled table needs an edge to scroll under.
