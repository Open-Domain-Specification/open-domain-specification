# Relationship detail opens in a bottom sheet, not a nested table row

Expanding a row of the Strategic position table renders `RelationshipDetail` inside a `colspan` cell, and that detail carries its own tables (the crossings table above all). A table inside a table row reads awkwardly: two header rows, two column rhythms and two hover treatments in one grid. Move that disclosure into a bottom sheet.

The health report's expanded row stays as it is: its detail is a comment list, not a table, and reads correctly inline.

- **dev-opus** (2026-09-05T16:30:00.000Z): Picked this up. Read the four files it turns on: `packages/pages/src/lib/organisms/StrategicPositionTable.svelte:76-84` passes `detail` to `DataTable`, which draws it as a `colspan` row at `packages/pages/src/lib/atoms/DataTable.svelte:212-214`; `packages/pages/src/lib/organisms/RelationshipDetail.svelte:128-160` is the crossings table inside it, and `packages/pages/src/lib/organisms/HealthReport.svelte:95` is the other `detail` caller that has to keep working. The design calls, each with its reason, before any code:
  1. **Fixed to the viewport bottom, inset from the site tree, not docked in the page column.** VS Code's panel is pinned to the bottom of the workbench and starts at the editor's left edge — it never runs under the side bar. A block docked at the end of the page column would scroll away from the row that opened it, which is the one thing this disclosure has to keep on screen. The inset is a custom property the shell sets (`--ods-panel-inset`, 260px in `packages/pages/assets/site.css:57`, 0 when embedded and 0 under 900px), so the sheet needs no JS to find its column.
  2. **Height `clamp(220px, 40vh, 560px)`, body scrolls, header fixed.** VS Code opens its panel at about a third of the window; 40vh leaves the majority of the table readable above it, the 220px floor keeps a title and two lines in a short window, and the 560px cap stops a tall monitor giving half the screen to one relationship.
  3. **Not resizable.** A drag edge needs a keyboard equivalent and a remembered size to earn its keep; the body scrolls and the relationship still has its own page for the long read. Recorded as a deliberate omission, not an oversight.
  4. **The page reserves the sheet's height while it is open** (`padding-bottom` on `document.body`), because a fixed panel that hides the last rows of the table is worse than the nested row it replaces.
  5. **The header names the view, not the row: "Relationship".** Problems, Output and Terminal name the panel, and the content names itself — `RelationshipDetail` already opens with both context lockups, the type and the disposition, so repeating that in the header would be two titles in six lines.
  6. **`role="region"` with `aria-labelledby`, not `dialog`.** There is no scrim and the page stays live, so this is a disclosure that happens to be docked; the toggle keeps `aria-expanded`/`aria-controls` and the sheet takes focus and returns it, which is what makes Escape honest.
