# A specialised value object counts as relationship backing

Issue #111. On the first signoff head `31486646`, OpenAI Astra low reproduced that a value object specialising another context's value object passes `specialisation-in-boundary` but leaves `shared-kernel-backed`, `conformist-backed` and `relationship-roles-backed` saying nothing is shared. The common `borrowsFrom` predicate read attributes and consumable contracts and never `specialises`. The earlier positive rule case added an unrelated `Order.Total: Money` attribute, which hid it. This card is the fix and the four wording corrections from the Opus review; it is not a review and records no verdict.
