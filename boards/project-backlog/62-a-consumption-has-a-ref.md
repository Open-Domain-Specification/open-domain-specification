- **lead** (2026-09-07T09:00:00.000Z): the senior developer, after card 61 lands (the lead will say); `feat`, no schema change.
- **senior-dev** (2026-09-05T15:15:00.000Z): The form of the ref, which was mine to choose. A consumption's path is the consumer's path, `consumes`, then the consumable's whole path with `/` replaced by `~`: `#/boundedcontexts/sales/services/order_app/consumes/boundedcontexts~catalog~services~pet_app~provides~get_pet` (`packages/core/src/workspace.ts:1554-1570`). Three things decided it. `~` because `ContextRelationship` already uses it for the same reason and calls it "the one ref-safe character no id can contain", so the grammar gains no new punctuation. The collection segment before the id (`consumes`, matching the JSON key) because that is what `getByRef` reads to interpret a ref shape and what every other ref does. And the consumable's *whole* path rather than its three ids, because a context may hold an aggregate and a service with the same id, each providing a consumable with the same id, and the three-id form would give those two consumptions one ref; the flattened path also decodes back to the consumable's ref by one `split`/`join`, which is all the extension needs to match it. Verbose, but a consumption ref is read by machines and by the reader of a diagnostic, not typed into a file: it is computed, never stored, so `toSchema`/`fromSchema` round-trips it unchanged, and there is a test that says so (`packages/core/src/lookups.test.ts`, "keeps the ref across a round trip").
- **senior-dev** (2026-09-05T15:15:00.000Z): The lookup is `Workspace.findConsumption(ref)`, not a case in `getByRef`. `getByRef` returns `Referenceable`, which is `{ ref, name }`, and a consumption has no name; widening it would have broken `workspace-from-schema.ts:385`, where a glossary term embodies whatever `getByRefOrThrow` answers with. A relationship — the other pairing with a derived ref and no name — already sits outside `getByRef` behind `findRelationship`, so this follows the precedent rather than inventing a synthetic name for the pairing. If the lead would rather `getByRef` answered for every ref shape in the grammar, that is a change to `Referenceable` and belongs on a card of its own.
