Processes are not in the model yet, so there is nothing to refuse there; when they arrive the rule is one more loop. `event-unraised` (`packages/core/src/validate.ts:1614-1640`, catalogued at `:2116-2125`) is a warning on an event no operation of its own context raises, skipped on an external context, and its fix text offers both answers — name the raiser, or move the event to the system that emits it and mark that context external. Every internals rule now reads `modelledContexts`, so an external context that (wrongly) declares an aggregate gets exactly one diagnostic saying so, not a cascade about its root entity, its identities and its tree. Rules about the *edge* — `schema-context`, `role-coherence`, `internal-consumable`, `raises-in-context`, `relationship-*` — still apply to an external context in full, because what it publishes and takes is the part we do depend on.
