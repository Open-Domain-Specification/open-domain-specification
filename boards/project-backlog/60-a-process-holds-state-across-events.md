- **optimus-prime** (2026-09-07T09:30:00.000Z): Ironhide-deep, justified by the reach: a new element kind touches every layer. After card 59 lands and decision 23 is Accepted (the lead will say); `feat!`.
- **ironhide-deep** (2026-09-05T16:30:00.000Z): **What makes the normal shape not a cycle, in one place.** `ReactionChain` registers a process's `starts` and `on` as what wakes it and answers `after(process)` with its `then`; `ends` registers nothing. So a process that issues an operation whose event ends it — the shape decision 23 calls normal — is walked as process → operation → event and stops, and `reaction-cycle` has no ring to find. A process that lists that same event under `on` as well *is* reported, because it really does trigger itself and nothing in the model says what stops it; there is a test for each of the two. The flow map draws the ending edge anyway, dashed and labelled `ends`, because "start events in, end events out" is what the card asked for and a reader needs to see where a lifecycle finishes; the edge carries `kind: "ends"` on `ODSFlowMapEdge` so the renderer can say it is not a step. That is the one place the drawn graph and the walked graph deliberately differ, and both the code and `apps/docs/docs/4-graphviz/4-flow.md` say so.
- **ironhide-deep** (2026-09-05T16:30:00.000Z): **Five processes, and why each chain was one.** The brief says a chain of two or more policies that expresses one process becomes one process, so I applied decision 23's own test — does it wait, and does it remember? — rather than merging every chain I found. **Petstore**: the three Sales policies (approve when available, reserve on approval, mark sold on delivery) are "Order fulfilment", starting on `OrderPlaced` and ending on `OrderDelivered`; the DISCOVERY record already admitted the correlation problem this fixes ("could not say how a PetStatusChanged led to an orderId"). **RiverMart**: "Checkout" (three policies; the code comment above them read "Checkout chains: cart checked out → authorise; authorised → place order") and "Order to delivery" (three policies, ending on `OrderCompleted` or `OrderCancelled`). **NorthBank**: "Instruction lifecycle" — its DISCOVERY literally recorded "seven policies chaining" what the Payments Hub lead described as one instruction going from initiated to settled — and "Customer onboarding", which holds a prospective customer between the screening request and the answer. **StreamLine**: "Master to publication", which is what holds the productionId→titleId match while the encode runs, a correlation the peer review had already flagged.
